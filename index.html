DOC-01

Dictalis

tax-compliance document automation and integrations

Re-architected the OCR pipeline from Celery to AWS Step Functions: a per-document Map over Fargate with per-item fault tolerance, so one bad PDF no longer takes down a batch of 1,500. The Celery watchdog was replaced by a token-and-heartbeat mechanism that reclaims stuck executions. All infrastructure as code, in SAM/CloudFormation.

The AI that reads the documents is swappable behind a single interface: the OCR_BACKEND switch picks an in-house OCR engine or AWS Textract, which also serves as a fallback path when the primary engine can't resolve a document. Changing engines is configuration, not a redesign.

Official document generation moved from an ad-hoc render to a controlled DOCX→PDF engine (headless LibreOffice inside the worker image) that produces the exact layout required by the SAT annex, with a digital-seal block and gap-free official folio numbers. It passes compliance without a single manual edit.

FLD-02

Flow computer & SCADA

tertiary element on a Raspberry Pi, FUXA HMI generated from code

The chain above, mounted on a 10.1" ED-HMI3020 panel with kiosk mode, watchdog and auto-start. The correction engine implements API MPMS 11.2.4 and 21.2 —CTL, CPL and their product CCF— and I ported it to Go.

The port's acceptance gate wasn't the standard's 18 published examples: those had already let a gamma60 truncation to five decimals slip through once. The gate was equivalence against the reference engine across the entire domain — 755,820 CTL cases, zero differences.

The dashboard isn't drawn in the FUXA editor: an idempotent script builds the whole project —MQTT device, 20 tags and 7 views— and publishes it through its API, so the HMI lives in version control and gets reviewed in a PR. The views include an ISA-5.1 P&ID per tank and paginate automatically to any number of tanks from a single config file.

Every build checks that nothing overflows the 1280×800 canvas and fails if anything does: in kiosk mode there's no scrollbar, so whatever overflows simply doesn't exist and raises no error. That check caught five layout bugs that only appear past three tanks, and revealed that FUXA was clipping the last 46 px of every view when hiding its header — the DOM was fine; it only showed up by probing the canvas point by point.

KEP-03

KEPServerEX → AWS

analog plant signals to the cloud

Reads tags from the KEPServerEX IoT Gateway over HTTP against the real server on the plant network, and lands them in S3 partitioned by the event date, not the upload date — the difference between partitioning you can query and partitioning that's only good for archiving. A malformed record is reported and skipped; it doesn't abort the batch.

As an alternate transport, a publisher to AWS IoT Core over MQTT with mutual TLS and QoS 1, packaged in Docker. Plus a hardware-free simulator to exercise the full pipeline without depending on plant or VPN access.

IoT Panel

operations console on top of the telemetry gateway

Eleven operations pages: multi-variable comparison with a shared dual Y axis, a custom signal-processing module (prepare, despike, smooth), intake detection by sustained rise and a compliance group. I built its design-token system and used it to eliminate every inline style.

After deployment I led stabilization for all seven clients: two to three weeks of daily validation each —about fifteen client-weeks— as the single technical point of contact.
